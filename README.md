# PG-VPS: Experiment Reproduction

This package reproduces the simulation experiments for **Progress-Guarded Model Predictive Control for Planar Pushing Under Geometric Uncertainty**.

It contains the required controllers, fixed experimental inputs, statistical analysis, and figure-generation scripts. It runs independently of the parent project. 

## 1. Installation

Run the following commands from this directory:

```bash
conda env create -f environment.yml
conda activate control
```

If the original `control` environment is already installed, activate it directly. Alternatively, use Python 3.11 and install the pinned dependencies:

```bash
python -m pip install -r requirements.txt
```

The experimental versions are MuJoCo 3.17.0, NumPy 2.4.6, SciPy 1.17.1, and Matplotlib 3.11.2. Numerical simulation requires neither a desktop session nor a GPU. OpenGL is needed only for rendering the MuJoCo snapshots.

## 2. Quick start

List the available datasets:

```bash
python reproduce.py list
```

Check the installation with short simulations:

```bash
python reproduce.py smoke --workers 2 --output /tmp/pgvps-smoke
```

The smoke check runs only three control cycles for each controller or parameter configuration. It verifies execution, not the paper's performance results.

Run all experiments, statistical analysis, and figure generation:

```bash
python reproduce.py all --workers 4
```

The main evaluation contains **3,744 episodes**, each with **400 control cycles**. Candidate-cost validation additionally reruns six PG-VPS episodes. A separate serial benchmark measures initial-planning latency on three fixed observed states, with one warm-up and three repeats per setting. Sampling baselines require substantially more prediction work than the policy-based controllers. Full reproduction can therefore take considerable time.

## 3. Run experiments separately

```bash
python reproduce.py run --study independent --workers 4
python reproduce.py run --study ablation --workers 4
python reproduce.py run --study sensitivity --workers 4
python reproduce.py run --study public --workers 4
python reproduce.py validate
python reproduce.py benchmark
python reproduce.py analyze
python reproduce.py figures
```

Analysis requires all seven datasets generated by these four study groups. Figure generation also requires the analysis output.

| Study | Experimental design | Episodes |
|---|---|---:|
| `independent` | PG-VPS, Fixed 0.65, and Fixed 0.95; 12 seeds, six polygon orders, and four friction/mass combinations | 864 |
| `ablation` | Six controllers combining compact or expanded policy bases with progress-dependent or fixed switching | 1,728 |
| `sensitivity` | Seven parameter configurations, each evaluated under 144 conditions | 1,008 |
| `public` | PG-VPS, PS, MPPI, CEM, iCEM, and Smooth-MPPI under 24 paired conditions | 144 |

The ablation group produces `pgtaiv_extended_confirmatory`, `pgtaiv_factorial_confirmatory`, and `pgvps_strict_confirmatory`. The public group produces `pgvps_public_subset` and `pgtaiv_public_baselines`. The remaining groups produce `pgvps_independent_confirmatory` and `pgvps_sensitivity`.

## 4. Output directories and resumption

By default, generated files are written under this package. To use a separate working directory, provide the same `--output` argument at every stage:

```bash
python reproduce.py all --workers 4 --output /path/to/workdir
```

After an interruption, resume with:

```bash
python reproduce.py all --workers 4 --output /path/to/workdir --resume
```

Completed episodes are skipped. Source files, configurations, and dependency versions are checked before resumption to avoid mixing incompatible runs. If these have changed, use a new output directory.

For debugging, run a limited number of full-length episodes:

```bash
python reproduce.py run --study independent --limit 3 --workers 1 --output /tmp/pgvps-debug
```

`--limit` applies separately to each selected dataset. Partial datasets cannot be used for the full statistical analysis. `--workers` controls process concurrency; numerical-library thread counts default to one unless already set in the environment.

## 5. Generated results

| Path | Contents |
|---|---|
| `results/<dataset>/summary.json` | Episode success, accumulated cost, completion time, and prediction work |
| `results/<dataset>/*.npz` | States, applied inputs, errors, and computation times |
| `results/<dataset>/*_plans.json` | Planning and switching records |
| `results/<dataset>/*_result.json` | Per-episode result checkpoints |
| `results/<dataset>/protocol.json` | Experimental inputs for the run |
| `results/<dataset>/provenance.json` | Source hashes and environment versions |
| `results/<dataset>/completion.json` | Dataset completion status |
| `results/pgvps_analysis/analysis.json` | Summary statistics, cluster-bootstrap intervals, Holm corrections, and decision analysis |
| `results/pgvps_analysis/*.csv` | Readable tables for independent performance, public comparisons, ablation, sensitivity, and verification outcomes |
| `figures/*.pdf` | Experimental comparison figures |

The results cover closed-loop performance and robustness, public-controller comparisons and computational efficiency, and mechanism validation, ablation and parameter sensitivity. Figures include the closed-loop snapshots, trajectories, error responses, inputs, switching, and all five public sampling baselines. Filenames identify results by content rather than manuscript figure numbers. The method architecture diagram and manuscript compilation are outside this package's scope.

Reference success counts in the independent evaluation are **272/288** for PG-VPS, **221/288** for Fixed 0.65, and **257/288** for Fixed 0.95. The analysis computes its results from generated trajectories; it does not return hard-coded table entries. Wall-clock time depends on hardware. The paper's main computational metric is the number of prediction physics substeps, and platform or dependency changes may introduce numerical differences.

## 6. Rendering over SSH

MuJoCo snapshot rendering defaults to EGL. To use an existing remote desktop:

```bash
MUJOCO_GL=glfw DISPLAY=:0 python reproduce.py figures
```

For software rendering, install the system OSMesa library and use:

```bash
MUJOCO_GL=osmesa python reproduce.py figures
```

Include `--output /path/to/workdir` if the experiment results are stored outside this package. Numerical simulation and statistical analysis do not require rendering.

## 7. Package layout and fixed inputs

```text
codeupdate/
  reproduce.py          # Unified execution entry point
  requirements.txt      # Pinned Python dependencies
  environment.yml       # Conda environment definition
  configs/              # Fixed experimental inputs
  research_platform/    # Required controller and simulation modules
  scripts/              # Simulation loops, statistical analysis, and plotting
  licenses/             # Upstream license notices
```

`configs/experiments.json` stores the true and estimated polygons, goals, seeds, noise levels, controller parameters, and public-baseline settings. Geometry and goals are deduplicated across 186 seed/shape pairs. These are experimental inputs, not precomputed outputs. Measurement noise uses `seed + 300000`; optimizer sampling uses `seed + 200000`.

The 22 controller and simulation modules retain their evaluated implementations and, where applicable, their original internal names. They form the runtime dependency set for the retained experiments.

## 9. Additional validation

`python reproduce.py validate` evaluates coarse, fine and reference costs for candidate sets sampled from six closed-loop tasks. Its outputs are in `results/decision_bounds/`. Reference predictions use the true plant parameters and a 1.25 ms integration step. These checks evaluate conditional inequalities; they do not certify online prediction errors.

`python reproduce.py benchmark` measures initial-planning calls at sample budgets of 32, 48, 64, 96, 128, 160, 192 and 256 on three fixed task states. Model construction is excluded, each configuration has a warm-up call, and three fresh-controller repeats are timed serially. Outputs and machine information are in `results/planning_benchmark/`. These measurements concern initialization, not worst-case steady-state execution or closed-loop performance at the alternative budgets.

The public-comparison plots use all 24 paired conditions. Success differences are aggregated by seed before exact paired sign-flip tests and Holm correction; success plots show observed fractions rather than independent-trial binomial intervals. All public methods appear in the time-response and friction--mass comparisons.
